# Hang Out application data inventory

Source assessment updated October 26, 2026 for the application candidate, including the default beta and the explicit opt-in Lobby session-authority mode. This records source behavior and limits, not a deployed revision or infrastructure deletion. Controlled consent and incident models do not collect real enrollment or case data merely because their code exists. Legal applicability and public release remain unqualified; see [privacy and incident handling](HANGOUT_PRIVACY_AND_INCIDENTS.md).

Closing a transport immediately fences further frames and releases delivery credit. It does not prove that the guest's membership was durably removed. In the opt-in authority mode, a refused disconnect or failed unbind retains its existing binding and necessary session metadata until retirement is confirmed. A bounded in-memory pending set contains only already-admitted connection references and cleanup status, with no new chat or media archive. At most one background cleanup attempt per failed retirement is followed by bounded work through the existing alarm; revoked sessions remain unconfirmed while their cleanup is pending. On cold recovery, the pruned session snapshot must commit before old bindings are retired.

Participation retention runs before the alarm's affirmative permission refresh. Each partition's record, reference/index cleanup and cursor update share one native transaction; failure rolls back that step, while earlier completed steps may remain. A structurally valid expired, unqualified or withdrawn policy can permit cleanup without providing a new grant. I1 evidence and holds are outside this C2 path. It does not release an allocator charge, complete parental rights, establish legal or provider retention, or erase infrastructure backups. Runtime qualification of this addition is pending; see [production participation](HANGOUT_PRODUCTION_PARTICIPATION.md).

Paths in the table are relative to `hangout-worker/src/` or the private preview asset directory as appropriate. Limits are independently scoped; a 24-hour report TTL does not shorten room ownership, browser storage, provider logs or infrastructure backups. The [session-authority guide](HANGOUT_SESSION_AUTHORITY.md) distinguishes the default registry from the opt-in mode and its migration/rollback requirements.

The [consent ledger](HANGOUT_PARTICIPATION_LEDGER.md), [controlled participation enforcement](HANGOUT_PARTICIPATION_ENFORCEMENT.md), [restricted incident primitives](HANGOUT_INCIDENT_CASE_PRIMITIVES.md) and [local incident-review interface](HANGOUT_INCIDENT_REVIEW.md) are implemented foundations exercised with explicit synthetic authority. Their own contracts describe purpose/revision/expiry records and restricted evidence. They are not default production enrollment or incident collection. Real identity/guardian decisions, appointed handlers, purpose keys, retention policy, storage integration and public workflows still need qualification before use.

Before public release, the deployment/legal owners must establish the actual controller/operator, processors and locations; backup/PITR and log retention; consent/parental rights handling; abuse and notice coverage; narrowly authorized preservation; and the source revision that is really deployed. The application session can prepare contracts, UI and tests; it cannot infer these answers from a healthy endpoint.
