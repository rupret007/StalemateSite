## First integration

1. Add a same-origin, protected match socket in the private Worker, using the existing admission route and lobby as the room and session authority. Start with the match endpoint handled by the same Durable Object that commits room membership. This lets leave, ban, block, Shield, expiry and room-instance replacement retire gameplay permissions in the same ordered path. Keep the game connection distinct from chat. The room shell is the stable top-level page while game panels swap in and out.
2. Issue short-lived, one-use grants over an admitted lobby connection for the current room instance, role and game capability. Bind each grant to the existing admitted session. Validate it on a same-origin upgrade, and keep raw session and device identifiers server-side. Preserve existing budget, participation and revocation rules. On an ordinary network break, restore a player's seat only after the same session regains admission to the current room instance. Explicit leave or revocation invalidates seat reclaim. Join/seat decisions stay outside the Chess reducer.
3. Route match commands through the lobby's ordered effects and storage path. Store plain versioned checkpoints with a bounded match lifetime, schedule the server deadline, and publish a viewer-specific state only after successful commit. Include timer-driven state changes even when a command is rejected for arriving after expiry. Keep match frames separate from chat quotas while counting their transport cost in the applicable service budget. Test a storage failure and a queued move concurrent with removal.
4. Mount the existing Chessground board and artwork inside the room with an online controller that takes position, color and clock from the server. Handle native tap, drag and keyboard, promotion, draw offers/claims, resign, rematch and reconnect. Package the exact public board assets the protected room needs through its existing asset builder. The builder currently excludes `play/`. Add the small explicit allowlist to the protected package while keeping the static arcade usable on its own.
5. Use the existing entry-site registry for Rad Dad and Stalemate branding. Add arcade entry links to the same private top-level room behind the capability, preserving each local arcade. Prove both entry paths with separate admitted browser contexts and keep the chat composer reachable at narrow and short heights.
