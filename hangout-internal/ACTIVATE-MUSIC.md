## Read-only account checks

1. **Cloudflare → Billing and Usage (90 sec).** Read the active plan, billing period and combined Realtime SFU and TURN egress. Record the remaining included egress and expected parallel account traffic. Cloudflare publishes 1,000 GB per month shared by SFU and TURN, then $0.05/GB. Use the allowance confirmed for this account. [Realtime pricing](https://developers.cloudflare.com/realtime/sfu/platform/pricing/)
2. **Workers and Durable Objects usage (60 sec).** Check remaining included requests, compute and storage for the applicable daily or monthly period. Confirm the demo fits those allowances after other workloads. If any required usage is unknown or would add a charge, pause at this step. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)
3. **Issuer usage and limits (90 sec).** Review current combined and web-key TURN ingress plus egress and the effective limits. The reviewed ceilings are 800 GB combined, 200 GB web, 3,000 web requests/day, 600-second credentials, one guest and 256 MiB per endpoint. Use any lower live limits. Budget up to 512 MiB per two-phone start and 2 GiB for the four planned starts, plus parallel and unreported traffic. Confirm fresh headroom again before each live window. The issuer caps govern admission and analytics can lag. [TURN analytics](https://developers.cloudflare.com/realtime/turn/analytics/)
4. **Serving versions (90 sec).** Read deployment weights, protected previews, approved origins, namespace and migration state, and binding names for `webjam-turn-credentials` and `stalemate-hangout-beta`. Confirm both current versions and that version preview URLs are disabled and serving site routes require admission. [Wrangler commands](https://developers.cloudflare.com/workers/wrangler/commands/)
5. **Recovery pair (60 sec).** Verify the proposed site rollback against the deployment receipt or version inventory. Record the full restorable version, asset and namespace compatibility, and rollback issuer version. This short reference remains unverified. Keep the release paused until the pair is confirmed. [Cloudflare rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)

## Action-time approvals

Begin these steps after the exact-head full gate and Karen pass for the matched release.

6. **Dedicated web TURN key (60 sec).** Confirm an existing approved dedicated web key can be reused. If absent, explicitly approve or decline creating it under **Realtime → TURN** in the existing account after the $0 checks pass. Use the approved vault flow.
7. **Staged issuer bindings (60 sec).** Approve each binding by name, `WEB_TURN_KEY_ID` and `WEB_TURN_KEY_API_TOKEN`. After both approvals, the operator stages them together through standard input in the approved vault-backed Wrangler session and verifies the binding names on the staged version. Use `wrangler versions secret bulk --name webjam-turn-credentials`. Preserve the desktop and existing account/analytics bindings and issuer state. [Wrangler commands](https://developers.cloudflare.com/workers/wrangler/commands/)
8. **Issuer origin (60 sec).** Approve any required `CORS_ALLOWED_ORIGINS` change using the exact origin from the approved protected deployment. Retain the existing public WebJam origin and approved entries. Keep private Music on the named `PrivateMusicIssuer` service with its room-scoped permit, and verify ordinary minting denies the protected origin.
9. **Protected site bindings (60 sec).** Approve the exact `WEBJAM_WEB_ORIGINS` value and `WEBJAM_PRIVATE_MUSIC` binding separately. The binding targets `webjam-turn-credentials` at entrypoint `PrivateMusicIssuer`. Keep `HANGOUT_TURN_ENABLED=0`, AI off, and preserve invite-only admission, signed consent and session authority, namespace, moderation and limits.
10. **Stage the qualified pair (90 sec).** Check the gated site commit and beta asset manifest and the matched issuer commit. Approve staging before the site upload. The operator builds the private assets with `npm run package:beta`, compares the manifest, tags the upload with the gated commit, and brings back the exact staged versions and binding readbacks. If the issuer pin changes, approve the new matched pair.
11. **G6 issuer promotion (60 sec).** With Step 5 verified, approve the exact staged issuer version if promotion is needed. Check the staged version and binding readback before making this decision.
12. **G6 private site promotion (60 sec).** Approve the exact staged site version after the issuer readback. Use the approved config and version IDs from the private receipt. The operator verifies serving versions and invite-only access after promotion.
13. **G7 live window (60 sec).** Repeat the read-only checks in Steps 1–3 before this decision. Approve each attended window and any separate credential-minting or forced-relay check. Use [REHEARSAL.md](REHEARSAL.md) for the two phones. If usage, admission, capture or cleanup differs from the approval, end the call, halt further issuance, and confirm revocation or expiry before another trial. Any rollback uses the verified pair and Jeff’s explicit go.
